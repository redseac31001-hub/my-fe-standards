## 概述

`/task` 是一个端到端的计划任务编排命令，它会：

1. **理解你的需求** - 分析输入，识别任务类型
2. **收集项目上下文** - 查询架构图谱、扫描相关代码
3. **分解为原子任务** - 按 INVEST 原则拆分
4. **请求你的确认** - 展示计划，等待审批
5. **自动执行任务** - 协调多个 Agent 完成工作
6. **追踪变更** - 记录所有偏离原计划的改动
7. **请求验收** - 生成报告，完成闭环

`/task` 是显式短命令；如果用户直接说“帮我实现这个需求”“帮我规划这次改造”，也应内部视为同一入口。两者都必须先经过 `task-intake-routing -> TaskBook.plan -> planner/output validator -> executor` 这条闭环链路，而不是当作自由聊天处理。

## 使用方法

### 基本用法

```
/task 实现用户登录功能
/task 重构订单处理模块
/task 添加暗黑模式支持
/task 修复购物车数量计算问题
```

### 带参数用法

```
/task --type=new-feature 实现商品搜索功能
/task --type=refactoring 优化首页加载性能
/task --type=debugging 排查支付失败问题
```

## 任务类型

| 类型 | 关键词 | 说明 |
|------|--------|------|
| `new-feature` | 实现、添加、开发 | 新功能开发 |
| `refactoring` | 重构、优化、清理 | 代码重构 |
| `debugging` | 修复、排查、解决 | Bug 修复 |
| `testing` | 测试、覆盖、验证 | 测试相关 |
| `code-review` | 审查、检查 | 代码审查 |

## 执行过程

### 并行执行

无依赖的任务会并行执行，提升效率：

```
task-1 (设计) ──────────────────────────────▶ done
task-2 (测试登录) ─┬─────────────────────────▶ done
task-4 (测试注册) ─┘  (并行)
task-3 (实现登录) ────────┬──────────────────▶ done
task-5 (实现注册) ────────┘  (并行)
task-6 (Token) ───────────────────────────▶ done
task-7 (审查) ────────────────────────────▶ done
task-8 (集成测试) ─────────────────────────▶ done
```

### 阻塞处理

遇到阻塞时会暂停并请求你介入：

```
⚠️ 任务阻塞: task-3 (实现登录 API 调用)
原因: 缺少后端 API 文档

请选择:
1. 提供解决方案
2. 跳过此任务
3. 终止整个计划
```

## Agent 协作

`/task` 会自动协调以下 Agent：

| Agent | 职责 |
|-------|------|
| structure-analyzer | 分析项目架构 |
| planner | 生成实施计划 |
| tdd-driver | 测试先行实现（RED→GREEN→REFACTOR） |
| code-reviewer | 代码质量审查 |
| build-fix | 构建失败自动诊断修复 |
| security-reviewer | 安全审查（按需） |
