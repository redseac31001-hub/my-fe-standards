# Discovery Questions

仅在用户原始描述不足以产出可执行 PRD 时追问。目标是补齐决策所需信息，而不是把整场需求访谈搬进对话。

## What To Clarify

- **Problem / Goal**: 这项功能解决什么问题，成功后应带来什么结果
- **Target User**: 谁会使用，谁不会使用
- **Core Actions**: 用户最关键的 1-3 个动作是什么
- **Scope Boundaries**: 当前版本明确不做什么
- **Success Criteria**: 如何判断需求完成且有效

## Question Format

使用编号问题，并给出 3-4 个字母选项。保留一个 `Other` 让用户补充自由文本。

示例：

```text
1. 这个功能的主要目标是什么？
   A. 提升新用户转化
   B. 减少重复人工操作
   C. 提高留存或活跃
   D. Other: [请补充]

2. 第一阶段面向谁？
   A. 新用户
   B. 现有用户
   C. 管理员/运营
   D. Other: [请补充]
```

## When To Skip Questions

可以直接写 PRD 的情况：

- 用户已经明确给出目标、用户、范围、关键流程
- 任务是对已有方案做整理，而不是从零定义
- 用户只需要把既有需求转成更规范的 PRD

## Minimal Question Set

如果信息很少，优先问这几类：

1. 目标是什么
2. 谁是目标用户
3. 核心流程是什么
4. 当前版本不做什么
5. 如何验收成功

## Guardrails

- 不要一次问超过 5 个问题
- 不要问实现细节，除非它会改变需求边界
- 不要把不确定内容写成既定事实
- 用户回答简略时，优先保留到 `Open Questions`，不要无限追问
