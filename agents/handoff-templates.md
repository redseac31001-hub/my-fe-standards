# Agent 交接模板

> 标准化的 Agent 间交接模板，确保上下文不丢失。上下文丢失是多 Agent 协作失败的首要原因。

---

## 使用指南

| 场景 | 使用模板 |
|------|---------|
| 将工作分配给另一个 Agent | 标准交接 (#1) |
| 任务通过验收 | QA 通过 (#2) |
| 任务未通过验收 | QA 失败 (#3) |
| 任务超过 3 次重试 | 升级报告 (#4) |

---

## 1. 标准交接模板

用于任何 Agent 间的工作转移。在 TaskBook 的 `handoffs[]` 数组中记录每次交接。

```markdown
# Agent 交接文档

## 元数据
| 字段 | 值 |
|------|------|
| **来源 Agent** | [agent-id]（如 tdd-driver） |
| **目标 Agent** | [agent-id]（如 code-reviewer） |
| **工作流步骤** | [step-id]（如 tdd_implement → review） |
| **TaskBook** | [taskbook-id] |
| **任务 ID** | [task-id] |
| **优先级** | [critical / high / medium / low] |
| **时间戳** | [ISO 8601] |

## 上下文
**当前状态**: [已完成的工作，具体描述]
**相关文件**:
- [file/path/1] - [内容说明]
- [file/path/2] - [内容说明]
**依赖**: [此工作依赖的已完成项]
**约束**: [技术、时间、资源约束]

## 交付要求
**需要完成**: [具体、可衡量的交付物描述]
**验收标准**:
- [ ] [标准 1 - 可衡量]
- [ ] [标准 2 - 可衡量]
- [ ] [标准 3 - 可衡量]
**参考材料**: [链接到规范、设计、先前工作]

## 质量期望
**必须通过**: [此交付物的质量标准]
**需要的证据**: [证明完成的方式]
**下一步交接**: [输出的接收者及其需要的格式]
```

## 2. QA 通过模板

当审查 Agent（code-reviewer、build-fix 等）确认任务通过时使用。

```markdown
# QA 结果: 通过

## 任务
| 字段 | 值 |
|------|------|
| **任务 ID** | [id] |
| **任务描述** | [description] |
| **执行 Agent** | [agent-id] |
| **审查 Agent** | [agent-id] |
| **尝试次数** | [N] / 3 |
| **时间戳** | [ISO 8601] |

## 结果: 通过

## 验证证据
**功能验证**:
- [x] [验收标准 1] - 已验证
- [x] [验收标准 2] - 已验证
- [x] [验收标准 3] - 已验证

**构建验证**: npm run build - 通过
**测试验证**: npm test - 通过（[N] 个测试，[覆盖率]%）
**代码质量**: 符合 clean-code 规范

## 备注
[观察、改进建议、正面评价]

## 下一步
→ task-orchestrator: 标记任务完成，推进到下一个任务
```

## 3. QA 失败模板

当审查 Agent 拒绝任务时使用。

```markdown
# QA 结果: 失败

## 任务
| 字段 | 值 |
|------|------|
| **任务 ID** | [id] |
| **任务描述** | [description] |
| **执行 Agent** | [agent-id] |
| **审查 Agent** | [agent-id] |
| **尝试次数** | [N] / 3 |
| **时间戳** | [ISO 8601] |

## 结果: 失败

## 发现的问题

### 问题 1: [类别] - [严重性: critical/high/medium/low]
**描述**: [问题的精确描述]
**预期**: [根据验收标准应有的行为]
**实际**: [实际发生的行为]
**证据**: [测试输出或截图]
**修复指令**: [具体、可操作的修复步骤]
**需修改文件**: [精确文件路径]

### 问题 2: [类别] - [严重性]
（同上格式）

## 验收标准状态
- [x] [标准 1] - 通过
- [ ] [标准 2] - 失败（见问题 1）
- [ ] [标准 3] - 失败（见问题 2）

## 重试指令
**给执行 Agent**:
1. 仅修复上述列出的问题
2. 不要引入新功能或改动
3. 修复完成后重新提交审查
4. 当前是第 [N] 次尝试，最多 3 次

**如果第 3 次仍失败**: 任务将升级到 task-orchestrator
```

## 4. 升级报告模板

当任务超过 3 次重试后使用。

```markdown
# 升级报告

## 任务
| 字段 | 值 |
|------|------|
| **任务 ID** | [id] |
| **任务描述** | [description] |
| **执行 Agent** | [agent-id] |
| **审查 Agent** | [agent-id] |
| **已用完尝试次数** | 3/3 |
| **升级至** | task-orchestrator |
| **时间戳** | [ISO 8601] |

## 失败历史

### 第 1 次尝试
- **发现问题**: [摘要]
- **执行修复**: [变更内容]
- **结果**: 失败 - [原因]

### 第 2 次尝试
- **发现问题**: [摘要]
- **执行修复**: [变更内容]
- **结果**: 失败 - [原因]

### 第 3 次尝试
- **发现问题**: [摘要]
- **执行修复**: [变更内容]
- **结果**: 失败 - [原因]

## 根因分析
**持续失败的原因**: [底层问题分析]
**是否系统性问题**: [一次性问题还是模式性问题]
**复杂度评估**: [任务是否被正确划分范围]

## 建议处理方式
- [ ] **重新分配** 给其他 Agent（[建议的 agent-id]）
- [ ] **分解** 为更小的子任务（[提议的分解方案]）
- [ ] **修改方案** - 需要架构/设计变更
- [ ] **接受现状** 并记录已知限制
- [ ] **延期** 到下一个迭代

## 影响评估
**阻塞项**: [被此任务阻塞的其他任务]
**时间线影响**: [对整体进度的影响]
**质量影响**: [接受现状会带来的质量妥协]

## 需要决策
**决策者**: task-orchestrator / 用户
**截止时间**: [需要决策的时间点]
```

## 在 TaskBook 中记录交接

每次 Agent 间交接时，在 TaskBook 的对应 `taskItem` 中添加交接记录：

```json
{
  "handoffs": [
    {
      "from": "tdd-driver",
      "to": "code-reviewer",
      "type": "standard",
      "timestamp": "2026-03-13T10:30:00Z",
      "context": "TDD 实现完成，3 个测试通过，提交审查",
      "deliverables": ["src/utils/parser.ts", "tests/parser.test.ts"]
    }
  ]
}
```

交接类型（`type`）取值：`standard` | `qa_pass` | `qa_fail` | `escalation`
