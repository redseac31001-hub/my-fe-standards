# 生产排查 Runbook

> 线上 bug、性能问题、数据异常的快速排查操作流程。

---

## 适用场景

- 用户反馈的功能异常（NaN、白屏、数据不对）
- 性能问题（页面卡顿、加载慢、内存泄漏）
- 控制台错误
- 数据不一致
- 环境相关问题（仅生产出现）

## 推荐工作流

**始终使用 `micro`（3 步）**，原因：
1. 时间敏感，需要快速定位和修复
2. 范围通常明确（已知症状）
3. 不需要 PRD 或架构分析
4. 修复通常集中在 1-3 个文件

---

## 操作步骤

### 步骤 1: 症状收集与分类

**信息收集检查清单**:
- [ ] 用户描述（什么功能、什么操作、什么结果）
- [ ] 频率（100% 复现？偶发？特定条件？）
- [ ] 影响范围（所有用户？特定角色？特定数据？）
- [ ] 环境信息（浏览器、操作系统、网络）
- [ ] 错误信息（控制台报错、网络请求异常）

**问题分类**:

| 类别 | 关键词 | 首选 Agent | 紧急度 |
|------|--------|-----------|--------|
| 数据异常 | NaN、undefined、数据不对 | bug-investigator | 高 |
| 功能故障 | 不生效、没反应、点击无效 | bug-investigator | 高 |
| 渲染异常 | 白屏、布局错乱、闪烁 | bug-investigator | 高 |
| 性能问题 | 卡顿、加载慢、内存占用 | performance-profiler | 中 |
| 构建问题 | 部署后异常、环境差异 | build-fix | 中 |

### 步骤 2: 分层调查

**bug-investigator 的调查层级**:

```
第 1 层: 症状确认
  → 复现步骤、影响范围、错误信息

第 2 层: 数据流追踪
  → API 响应 → Store 状态 → 组件渲染
  → 确定问题在哪一层

第 3 层: 代码定位
  → 精确到文件和行号
  → 分析根因（类型、逻辑、竞态、边界）

第 4 层: 修复验证
  → 编写回归测试
  → 实现修复
  → 确认修复有效且无副作用
```

### 步骤 3: 修复与验证

**修复原则**:
1. **防御优先**: 修复根因，同时添加防御代码
2. **最小改动**: 只改必要的代码，不重构
3. **回归测试**: 必须补充测试覆盖修复场景
4. **验证完整**: `npm test` + `npm run build` 全部通过

**修复后检查清单**:
- [ ] 根因已修复（不是绕过）
- [ ] 回归测试已添加
- [ ] 原有测试未受影响
- [ ] 构建通过
- [ ] 修复不引入新问题

## 常见问题速查

### 数据类型不一致

**症状**: NaN、undefined、类型错误
**常见原因**: 后端返回类型不一致（string/number/null 混用）
**修复模式**:
```typescript
function safeNumber(value: unknown): number {
  if (value === null || value === undefined) return 0;
  const parsed = Number(value);
  return Number.isFinite(parsed) ? parsed : 0;
}
```

### 异步竞态

**症状**: 数据偶发错乱、显示旧数据
**常见原因**: 快速切换页面/标签时请求返回顺序不确定
**修复模式**:
```typescript
// 使用 AbortController 取消过期请求
const controller = new AbortController();
onUnmounted(() => controller.abort());
```

### 响应式丢失

**症状**: 数据更新了但界面没变
**常见原因**: 直接赋值替换了响应式对象，或解构丢失响应性
**修复模式**:
```typescript
// 错误: 解构丢失响应性
const { count } = store;

// 正确: 使用 storeToRefs
const { count } = storeToRefs(store);
```

### 路由守卫异常

**症状**: 页面白屏、无限重定向
**常见原因**: 路由守卫中的异步操作未正确处理
**修复模式**:
```typescript
router.beforeEach(async (to, from) => {
  try {
    const isAuth = await checkAuth();
    if (!isAuth && to.meta.requiresAuth) {
      return { name: 'login' };
    }
  } catch {
    return { name: 'error' };
  }
});
```

## 紧急修复流程

**当线上问题影响大量用户时**:

```
1. 确认症状和影响范围（5 分钟）
2. 选择 micro 工作流启动
3. bug-investigator 快速定位（15 分钟）
4. 编写修复 + 回归测试（15 分钟）
5. 验证: npm test + npm run build（5 分钟）
6. 验收关闭（5 分钟）

目标: 45 分钟内完成修复
```

```
[页面名称] 加载很慢/卡顿。
用户环境：[浏览器/设备]
数据量：[列表行数/接口数据量]

```
