# 功能开发 Runbook

> 新功能开发（组件、页面、API 集成）的标准操作流程。

---

## 适用场景

- 新建 Vue 组件、页面或 composable
- 集成新的后端 API
- 添加新的业务模块
- 扩展现有功能

## 推荐工作流

| 规模 | 工作流 | 说明 |
|------|--------|------|
| 小型（1 个组件、< 100 行） | `micro` | 快速实现，跳过审查 |
| 中型（多个文件、< 500 行） | `sprint` | 标准流程，含审查 |
| 大型（跨模块、> 500 行） | `default` | 完整流程，含 PRD |

---

## 操作步骤

### 步骤 1: 启动

```
用户: "帮我实现 [功能描述]"
→ task-orchestrator 识别为 new-feature
→ 自动选择工作流档位
```

**决策点**: 如果用户只要规划方案（不编码），使用 `planner` Agent。

### 步骤 2: 上下文收集

**检查清单**:
- [ ] 读取 `manifest.json` 确认技术栈
- [ ] 运行 structure-analyzer 获取架构快照
- [ ] 搜索已有的相似实现（至少 3 个）
- [ ] 确认测试框架和命名约定
- [ ] 识别可复用的工具函数和组件

**常见复用来源**:
```
src/utils/         → 工具函数
src/composables/   → 可复用逻辑
src/components/    → 基础组件（BaseInput, BaseModal 等）
src/api/           → API 封装模式
src/stores/        → Store 模式
```

### 步骤 3: 任务分解

**INVEST 原则检查**:
- [ ] Independent - 每个任务可独立执行
- [ ] Negotiable - 可协商调整范围
- [ ] Valuable - 有明确业务价值
- [ ] Estimable - 可估算工作量
- [ ] Small - 单个任务 < 200 行改动
- [ ] Testable - 有明确的验收标准

**典型任务序列**:
```
1. 接口设计（类型定义）
2. 编写测试（TDD RED）
3. 核心实现（TDD GREEN）
4. 组件/页面实现
5. 路由集成
6. 代码审查
7. 验收
```

### 步骤 4: TDD 实现

**每个实现任务必须遵循**:
```
RED:   编写失败测试 → 运行确认失败
GREEN: 最小实现通过测试 → 运行确认通过
REFACTOR: 优化代码 → 运行确认仍通过
```

**smoke gate 检查点**:
- 每个批次完成后运行 `npm test`
- 失败时进入 build-fix 修复循环（最多 3 次）
- 3 次失败后升级到用户

### 步骤 5: 审查（sprint/default）

**code-reviewer 检查项**:
- 类型安全（无 any）
- 命名规范（遵循项目约定）
- 复用检查（未重复造轮子）
- 测试覆盖（>= 80%）

### 步骤 6: 验收

**最终验证**:
```bash
npm run build   # 构建通过
npm test        # 测试通过
```

**验收标准**:
- 所有功能需求已实现
- 测试覆盖率 >= 80%
- 代码审查通过
- 构建无错误

---

## 常见问题处理

| 问题 | 处理方式 |
|------|---------|
| 依赖的 API 还没开发 | Mock API 数据，标记为已知限制 |
| 性能不达标 | 触发 performance-profiler 分析 |
| 安全审查未通过 | 触发 security-reviewer 提供修复建议 |
| 第三方库冲突 | 在 TaskBook 中记录为 blocked，请求用户决策 |

## Prompt 模板

### 启动功能开发
```
帮我实现 [功能名称]。
技术要求：[Vue 3/React/etc]
参考：[已有类似功能的路径]
约束：[性能要求/兼容性/etc]
```

### 仅做规划
```
帮我规划 [功能名称] 的实现方案。
需要：任务分解、风险评估、技术选型对比。
不需要编码。
```
