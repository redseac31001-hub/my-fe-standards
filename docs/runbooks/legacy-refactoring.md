# 遗留重构 Runbook

> 旧代码迁移、架构升级、技术债清理的标准操作流程。

---

## 适用场景

- jQuery / 原生 JS 迁移到 Vue 3
- Options API 迁移到 Composition API
- 大型模块拆分（单体 → 模块化）
- 技术债务清理（重复代码、过时依赖）
- 框架版本升级（Vue 2 → Vue 3、Webpack → Vite）

## 推荐工作流

**始终使用 `default`（7 步）**，原因：
1. PRD 阶段明确迁移范围和不迁移的部分
2. 架构分析识别遗留代码的依赖关系
3. 完整 TDD 保护网防止功能回归
4. 独立的构建修复步骤处理类型兼容问题

---

## 操作步骤

### 步骤 1: 范围界定

**必须回答的问题**:
- [ ] 迁移范围是什么？（哪些文件/模块）
- [ ] 是否需要向后兼容？
- [ ] 哪些功能可以删除？
- [ ] 有哪些外部依赖需要替换？

**风险等级评估**:

| 风险等级 | 条件 | 处理 |
|---------|------|------|
| 高 | > 1000 行、跨多模块、无测试 | 分阶段迁移，每阶段独立验证 |
| 中 | 500-1000 行、单模块、部分测试 | 一次性迁移，TDD 保护 |
| 低 | < 500 行、有测试 | 直接重构 |

### 步骤 2: 架构分析

**structure-analyzer 必须输出**:
- 遗留模块的文件清单和行数
- 外部依赖列表（jQuery 插件、旧版 API 等）
- 现有的 Vue 替代品（已有哪些可复用的组件/composable）
- 依赖关系图（谁依赖遗留模块）

**module-mapper 必须输出**:
- 遗留模块的导入/导出关系
- 被其他模块引用的公共 API
- 可以安全删除的内部实现

### 步骤 3: 迁移策略

**推荐的分层迁移顺序**:

```
1. 数据层（API 封装）     → 最底层，无 UI 依赖
2. 状态层（Store/State）   → 依赖数据层
3. 逻辑层（Composables）  → 依赖状态层
4. 视图层（Components）    → 依赖所有层
5. 集成层（路由/导航）     → 最后接入
6. 清理层（删除遗留代码） → 确认全部替换后
```

**每一层的任务模式**:
```
编写接口类型 → 编写测试 → 实现 → 验证 → 下一层
```

### 步骤 4: TDD 实现

**重构专用的测试策略**:

1. **先写"行为等价"测试**: 测试应该描述业务行为，而非实现细节
2. **对比旧实现输出**: 用旧代码的输出作为新测试的期望值
3. **逐个替换**: 不要一次性重写所有代码
4. **每个批次跑 smoke**: 确保渐进式替换不破坏已有功能

**批次划分建议**:
- 高风险（核心业务逻辑）: 最多 3 个文件/批次
- 中风险（UI 组件）: 最多 10 个文件/批次
- 低风险（配置/工具）: 最多 25 个文件/批次

### 步骤 5: 代码审查

**重构专用审查项**:
- [ ] 功能等价性: 所有旧功能在新实现中可用
- [ ] 依赖清除: 不再引用遗留模块
- [ ] 类型安全: 无 any，无 @ts-ignore
- [ ] 模式一致: 遵循项目现有的 Vue 3 模式
- [ ] 文件清理: 遗留代码已删除

### 步骤 6: 构建修复

**常见的迁移构建问题**:

| 问题 | 原因 | 修复 |
|------|------|------|
| 类型错误 | 旧代码无类型，新代码严格类型 | 补充类型定义 |
| 路径别名 | 旧路径不存在 | 更新 import 路径 |
| 缺少依赖 | 删除旧依赖后缺失 | 安装新依赖 |
| 全局变量 | jQuery $ 不再存在 | 替换为 Vue API |

### 步骤 7: 验收

**迁移专用验收检查**:
- [ ] 所有旧功能可用
- [ ] 遗留代码已完全删除
- [ ] 无 jQuery 残留引用
- [ ] 测试覆盖率 >= 80%
- [ ] 性能不低于旧版本
- [ ] 构建体积不显著增加

---

## 分阶段迁移策略（大型项目）

对于 > 1000 行的遗留模块，建议分阶段进行：

```
阶段 1: 数据层 + 状态层（1-2 天）
  → 独立验证，不影响 UI
  → 可以与旧 UI 并行运行

阶段 2: 核心视图组件（2-3 天）
  → 逐个替换页面/组件
  → 每个组件独立测试

阶段 3: 集成 + 清理（1 天）
  → 接入路由
  → 删除遗留代码
  → 最终验收
```

每个阶段独立运行 default 工作流的 Phase 4-6。
